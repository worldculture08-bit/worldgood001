When you install a new app, work seems like it will finally get organized. For a moment it does. Then the tools multiply and you forget where you used what. When tool fatigue stacks on top of fatigue on site, recording is the first thing you give up.

I try to reduce tools and fix the **flow** instead. When the flow is simple, even a tired day moves something forward.

## The minimum flow

1. Take notes on site (phone or paper notebook)
2. Move them into an organizing note the same day
3. Shape into a post only what you want to publish
4. If needed, let AI help with structure and wording only

The calendar blocks "when to write", notes block "what to write", and AI helps with "how to refine". When roles overlap, only confusion grows. Keeping the same content copied in three places feels like tidying but actually widens the fan of obligations.

## The checking question

Rather than showing off tools, it is better to check **whether yesterday's note became today's post**. If it did not, it is not time to change tools but time to see where the flow is blocked. Most often the blockage sits between "site → organizing". Try fixing that gap at ten minutes.

A good tool does not announce its own existence. A record left behind and work moving forward is enough.

## When to change tools

There are times you really should change. When search does not work, when the team cannot share the same space, or when there is a security risk. In that case, make a short migration plan: what moves, what is dropped, and when the old tool is closed. To keep the migration itself from becoming work, it is better not to go past two weeks.

In the first week of a new tool, check that the existing minimum flow still works before exploring new features. If the flow works and the features fall short, add the features then.
