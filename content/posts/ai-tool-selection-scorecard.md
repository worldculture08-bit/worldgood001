새 도구는 늘 매력적으로 보입니다. 데모는 빠르고, 가격표는 단순하고, 기능 목록은 길어 보입니다. 하지만 도구를 고르는 일은 기능 비교가 아니라 **우리 업무의 위험과 흐름을 도구에 맞출 수 있는지 확인하는 일**입니다. 가격은 그다음입니다.

## 1. 데이터 경계

가장 먼저 확인할 것은 “이 도구에 어떤 자료를 넣어도 되는가”입니다. 같은 AI 도구라도 요금제와 설정에 따라 입력 데이터를 학습에 사용하는지, 보관 기간이 얼마인지, 관리자 통제가 가능한지가 달라집니다.

- 고객 이름·연락처·계약 정보가 입력되는가
- 학습 사용 여부와 보관 기간을 설정할 수 있는가
- 관리자만 접근할 수 있는 권한 구분이 있는가
- 삭제 요청과 데이터 내보내기가 가능한가

이 질문에 답하지 못하는 도구는 기능이 좋아도 먼저 도입하지 않습니다. 관련 기준은 [AI 업무에서 개인정보를 다루는 방법](/p/privacy-in-ai-work)에 정리해 두었습니다.

## 2. 출력의 소유권과 내보내기

AI가 만든 초안, 문서, 코드의 사용 권한이 누구에게 있는지 확인합니다. 또한 도구를 그만둘 때 데이터를 어떤 형식으로 가져올 수 있는지도 중요합니다. 내보내기가 어려운 도구는 장기적으로 잠금 효과가 커집니다.

## 3. 기존 업무 흐름과의 연결

도구가 우리가 이미 쓰는 캘린더, 문서, 메신저, 저장소와 연결되는지 봅니다. 연결이 없으면 사람이 복사·붙여넣기로 다리를 놓아야 하고, 그 반복이 자동화의 효과를 지웁니다. 반대로 연결이 많다고 좋은 것도 아닙니다. 필요한 연결만 있는지 확인합니다.

## 4. 도입·교육·유지 비용

구독료 외에 숨은 비용을 계산합니다.

- 초기 설정과 관리자 교육 시간
- 팀원이 익숙해질 때까지의 생산성 저하
- 권한·계정 관리 업무
- 실패했을 때 되돌리는 비용

무료 요금제는 기능·인원·보관 기간 제한이 있는 경우가 많습니다. “무료로 시작”과 “우리 팀에서 계속 무료로 쓸 수 있음”은 다른 말입니다.

## 5. 검증 부담

AI 도구는 결과를 그대로 쓸 수 없다는 전제로 평가합니다. 도구가 만든 결과를 확인하는 데 드는 시간이 절약 시간보다 크면 도입 의미가 없습니다. 출처 표시, 원문 대조, 숫자 검증 기능이 있는지 확인합니다.

검증 방법 자체는 [AI 결과를 그대로 쓰지 않기 위한 검증 절차](/p/ai-output-verification)에서 다룹니다.

## 6. 가격 구조의 투명성

가격은 숫자만 보지 않습니다.

- 사용자당인지, 사용량 기반인지
- 초과 사용 시 어떻게 청구되는지
- 연간 약정과 해지 조건
- 세금·환율·결제 수단

도입 후 청구서가 예상과 크게 달라지는 도구는 업무 도구가 아니라 비용 리스크가 됩니다. 예산 담당자와 함께 상한선을 정해 두는 편이 좋습니다.

## 7. 종료 계획

마지막으로 “이 도구를 6개월 뒤 그만두려면 무엇이 필요한가”를 적습니다. 데이터 이전, 대체 도구, 계약 해지, 사용자 교육을 미리 생각해 두면 도구 선택의 기준이 훨씬 선명해집니다.

## 도입 전 2주 시험표

후보 도구는 기능 설명이 아니라 실제 업무로 시험합니다.

1. 업무 하나를 정한다.
2. 기존 방식과 새 도구 방식의 소요 시간을 적는다.
3. 오류와 되돌리기 횟수를 적는다.
4. 팀원 한 명에게 써 보게 하고 의견을 듣는다.
5. 2주 뒤 계속·보류·중단을 결정한다.

이때 “좋았다”는 의견보다 “어떤 입력에서 어떤 오류가 났는가”가 더 중요한 자료입니다.

## 자주 하는 실수

- 데모가 좋아 보인다는 이유로 도입을 결정한다
- 보안 검토를 나중으로 미룬다
- 무료 요금제 한도를 팀 전체 기준으로 계산하지 않는다
- 한 사람의 사용성만 보고 전사 도입을 정한다
- 종료 계획 없이 연간 계약을 맺는다

좋은 도구는 일을 대신하는 도구가 아니라, 사람이 판단하기 쉬운 형태로 일을 보여 주는 도구입니다. 이 기준은 [도구를 고르기 전에 사람의 흐름을 본다](/p/people-before-tools)에서 더 자세히 설명합니다.
