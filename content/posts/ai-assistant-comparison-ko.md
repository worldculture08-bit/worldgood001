업무용 AI를 고를 때 가장 흔한 실수는 “무엇이 제일 좋은가”를 먼저 묻는 것입니다. 정답은 없습니다. 세 도구는 잘하는 일이 다르고, 같은 도구라도 **우리 팀의 데이터·권한·업무 흐름**에 따라 평가가 뒤집힙니다.

그래서 이 글은 순위를 매기지 않습니다. 대신 **어떤 일을 어디에 나눠 맡길지** 판단하는 기준을 정리합니다.

## 한 도구로 다 하려 하면 생기는 일

한 도구에 모든 일을 몰아넣으면 세 가지가 따라옵니다.

1. **약한 영역의 실수가 쌓인다.** 긴 문서 정리에 강한 도구를 짧은 문서 초안에만 쓰면 낭비이고, 반대로 초안에 강한 도구로 계약서를 통째로 요약시키면 위험합니다.
2. **요금이 겹친다.** 팀원마다 다른 도구를 쓰면 같은 기능에 돈을 두 번 냅니다. [AI·SaaS 구독료 점검표](/p/ai-subscription-audit)에서 이 부분을 다룹니다.
3. **검증 책임이 흐려진다.** 어느 도구가 어떤 결과를 냈는지 기록이 없으면, 나중에 오류를 되짚을 수 없습니다. [AI 결과 검증 절차](/p/ai-output-verification)가 필요한 이유입니다.

## 세 도구를 나누는 기준

기능 목록은 금방 바뀝니다. 대신 **일의 성격**으로 나눕니다.

| 일의 성격 | 판단 기준 | 확인할 것 |
|---|---|---|
| 짧은 초안·아이디어 | 대화 속도, 문체 조절 | 대화 맥락 유지, 한국어 자연스러움 |
| 긴 문서 읽기·요약 | 입력 길이, 인용 정확도 | 출처 표시, 원문 대조 기능 |
| 표·숫자 정리 | 파일 업로드, 계산 | 계산 과정 설명, 환각 여부 |
| 검색·최신 정보 | 출처 신뢰도, 링크 | 원문 링크 제공 여부 |
| 조직 도구 연결 | 메일·문서·캘린더 연동 | 관리자 권한, 데이터 보관 |

이 표를 팀 회의에서 한 번 채우면, “누가 무슨 도구를 쓰는가”가 자연스럽게 정리됩니다.

## 1. 짧은 초안과 아이디어 정리

메일 답장, 공지 초안, 회의 안건 정리처럼 **짧고 반복적인 글**은 어떤 도구든 잘합니다. 이때는 정확도보다 **문체와 톤을 얼마나 쉽게 맞출 수 있는가**가 갈림길입니다. 사내 말투 예시를 몇 개 붙여 두고 “이 톤으로”라고 지시하는 방식이 잘 먹습니다.

프롬프트를 매번 새로 쓰는 대신 저장해 두면 품질 편차가 줄어듭니다. [AI 프롬프트 기록장](/p/ai-prompt-logbook)에서 이 방법을 설명합니다.

## 2. 긴 문서 읽기와 요약

보고서·계약서·회의록처럼 긴 문서는 **입력 길이**와 **인용 정확도**가 핵심입니다. 요약이 매끄러워도 원문에 없는 내용을 섞으면 위험합니다. 그래서 다음을 확인합니다.

- 요약에 **문서의 어느 부분**에서 나왔는지 표시할 수 있는가
- 숫자·날짜·고유명사를 원문과 대조할 수 있는가
- “문서에 없는 내용”이라고 답할 수 있는가

요약 품질은 도구보다 **지시문**에서 갈리는 경우가 많습니다. “3줄 요약”보다 “결정 사항·담당·기한으로 나눠 표로” 가 실제 업무에 쓸모 있습니다.

## 3. 표와 숫자

표 정리와 간단한 계산은 강력하지만, **계산 과정을 설명하게 하고** 다시 검산하는 습관이 필요합니다. 합계·평균·증감률은 눈으로 한 번, 계산기로 한 번 확인합니다. 틀린 숫자는 문장 오류보다 훨씬 큰 피해를 냅니다.

## 4. 검색과 최신 정보

“지금 이 도구 가격은?” 같은 질문은 모델 내부 지식으로 답하면 자주 틀립니다. 검색을 붙인 모드라도 **원문 링크를 열어 확인**해야 합니다. 자료를 읽는 방법은 [공공 자료를 읽는 법](/p/public-data-reading)에서 더 다룹니다.

## 5. 조직 도구와의 연결

실제 생산성은 “모델 성능”보다 **메일·문서·캘린더·저장소와 얼마나 자연스럽게 붙는가**에서 나옵니다. 연결이 많을수록 편하지만, 그만큼 **권한과 데이터 경계**를 확인해야 합니다. [AI 업무에서 개인정보를 다루는 방법](/p/privacy-in-ai-work)을 함께 보세요.

## 같은 입력으로 비교하는 방법

도구를 바꿀지는 감이 아니라 **실험**으로 정합니다.

1. 실제 업무 문서 1개를 고른다 (민감 정보는 가린다).
2. 같은 지시문으로 세 도구에 넣는다.
3. 결과를 **정확성·문체·되돌리기 횟수·소요 시간**으로 적는다.
4. 팀원 한 명이 다른 문서로 반복한다.
5. 2주 뒤 “무엇을 어디에 쓸지” 한 줄로 정한다.

이때 “느낌이 좋았다”보다 **“무엇을 틀렸는가”**가 좋은 자료입니다.

## 요금제는 어떻게 비교하나

가격표 숫자만 보면 안 됩니다.

- 사용자당인지, 사용량 기반인지
- 대화·파일·보관 한도가 얼마인지
- 팀 관리자 기능이 무료 요금제에도 있는지
- 초과 사용 시 청구가 어떻게 되는지

무료 요금제 한도는 **팀 전체 기준**으로 다시 계산합니다. 요금제는 자주 바뀌므로 각 서비스 공식 페이지에서 직접 확인하는 편이 안전합니다. 무료와 유료의 경계는 [AI 요금제 무료 vs 유료 판단 기준](/p/ai-plan-free-vs-paid)에서 자세히 다룹니다.

## 자주 하는 실수

- 벤치마크 점수만 보고 우리 업무 성능을 짐작한다
- 한 사람의 사용성만 보고 팀 전체 도입을 정한다
- 무료 요금제 한도를 개인 기준으로 계산한다
- 검증 절차 없이 결과를 그대로 쓴다
- 도구를 바꿀 때 기존 기록·프롬프트를 옮기지 않는다

## 도입 전 체크리스트

- [ ] 어떤 자료를 넣어도 되는지 정했다
- [ ] 역할별로 도구를 나눴다 (초안 / 요약 / 숫자 / 검색)
- [ ] 같은 입력 비교 실험을 했다
- [ ] 검증 절차와 담당자를 정했다
- [ ] 요금 상한과 종료 계획을 적었다

도구는 판단을 대신하지 않습니다. 판단하기 쉬운 형태로 일을 보여 줄 때만 쓸모가 있습니다. 이 관점은 [도구는 마법이 아니다](/p/tools-not-magic)와 [도구보다 사람의 흐름을 먼저 본다](/p/people-before-tools)에서 이어집니다.
